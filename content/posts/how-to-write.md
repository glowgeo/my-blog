部署完成后，你会在 `你的网址/admin/` 看到一个图形化写作后台。它叫 **Decap CMS**，完全免费、开源。

## 怎么进后台

1. 打开 `https://你的网址/admin/`
2. 点 **Login with Netlify Identity**
3. 输入你被邀请时设置的邮箱和密码

首次使用需要先在 Netlify 后台给自己发一封邀请邮件并设置密码。具体步骤在《上线操作指南》里。

## 界面长什么样

左侧是内容列表，顶部是 **New 文章** 按钮。点进去就是一个标题 + 正文编辑器的表单，跟 WordPress 很像：

| 字段 | 说明 |
|---|---|
| **标题** | 文章标题，会显示在页面顶部 |
| **发布日期** | 决定文章排序。时间越新越靠前 |
| **草稿** | 打开后文章**不会**发布到线上，只有你自己能看到 |
| **摘要** | 显示在首页列表里的简介。留空的话 Hugo 会自动截取正文开头 |
| **标签** | 用于归类，比如「教程」「随笔」。会生成标签页 |
| **分类** | 比标签更粗的归类 |
| **封面图** | 可选。设置后首页列表会显示缩略图 |
| **正文** | Markdown 编辑器，支持拖拽上传图片 |

写完点右上角的 **Publish** 就提交了。

## 点了发布之后发生了什么

Decap CMS 做的事是：**把内容写成 Markdown 文件，然后提交到你的 GitHub 仓库**。

然后 Netlify 检测到仓库有新提交 → 自动重新构建整个站点 → 大约 30 秒到 1 分钟后，你的新文章就上线了。

所以「发布」不等于「立刻能看到」，会有一小段延迟。这是正常的。

## 几个容易踩的坑

### 1. 图片上传到哪里了

图片会被放进 `static/images/uploads/`，在文章里以 `/images/uploads/xxx.jpg` 引用。

**建议**：上传前先自己压缩一下图片。原图动辄 5 MB，会让页面变慢。可以用 [Squoosh](https://squoosh.app/) 这类免费工具压到 200 KB 以内。

### 2. 草稿状态的陷阱

Hugo 的配置里 `buildDrafts: false`，所以**草稿状态的文档不会出现在线上站点里**——但文件已经提交到 GitHub 仓库了。

如果你想彻底删掉一篇文章，在后台左下角菜单里选 **Delete entry**，而不是只把草稿开关打开。

### 3. 中文文件名和网址

文章的网址默认由「日期 + 标题」生成。标题是中文时，网址里也会带中文，看起来是这样的：

```
https://你的网址/posts/2026-09-22-你好世界/
```

这个网址**能正常访问**，只是分享出去时会被转义成一长串 `%E4%BD%A0...`，不太好看。

如果你在意这个，可以这样做：新建文章时**用英文写标题**，然后在正文最前面用一级标题写中文标题。或者干脆接受它——Google 和百度都能正常索引中文网址。

### 4. 想改站点的标题和简介

那些在 `hugo.yaml` 里，不在后台里。改完保存并推送到 GitHub 即可。

## Markdown 快速参考

````markdown
# 一级标题
## 二级标题
### 三级标题

**加粗**  *斜体*  `行内代码`

- 无序列表
- 第二项

1. 有序列表
2. 第二项

> 引用文字

[链接文字](https://example.com)

![图片说明](/images/uploads/photo.jpg)

```js
console.log("hello")
```
````

标题层级建议从 `##` 开始用，因为文章标题本身已经是 `#` 了。站内的「目录」功能就是根据 `##` 和 `###` 自动生成的。

## 备份

你的文章存在 GitHub 上，本身就是一份完整备份。想额外保险的话：

- 定期把整个仓库 `git clone` 到本地
- 或者在 GitHub 仓库页面点 **Code → Download ZIP** 下载一份

这就够了。没有数据库，就没有「数据库备份」这个烦恼。
